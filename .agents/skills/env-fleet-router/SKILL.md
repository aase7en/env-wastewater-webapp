# ENV-Fleet-Router

Use `python scripts/env_autonomy_runtime.py route --task-category <category>` to report task fit. The command never calls a provider. For `independent_review`, `--review-risk-tier R2` (the default) reports the fresh GLM-5.3 MAX reviewer route and `--review-risk-tier R3` reports the required GPT-6.1 Sol cross-model route.

| Task category | Candidate route | Boundary |
| --- | --- | --- |
| `orchestration`, `routine_integration`, `low_risk_analysis` | GPT-6 Luna MAX | Owner-supervisor/control work under the active mission |
| `core_engineering`, `security`, `data_contract`, `bounded_implementation` | GLM-5.3 MAX via `cointh-glm` | Requires separately refreshed proxy-quota and upstream readiness evidence |
| `read_only_analysis` | GLM-5.3 Flash via `cointh-glm` | Read-only; same live admission and durable receipt requirements |
| `independent_review` (R2 ordinary) | Fresh GLM-5.3 MAX reviewer context | Separate read-only execution from the authoring lane; frozen exact SHA; adversarial; never the author's own run/session. Do not escalate ordinary R2 to a cross-model reviewer merely for model diversity |
| `independent_review` (R3 critical) | GPT-6.1 Sol | REQUIRED for deterministic R3 scope: auth/security/secrets, durable claim/protocol authority, concurrency/leases/retries/replay safety, provider admission/quota logic, release trust paths, high-blast-radius shared state, ambiguous destructive/data-loss risk. Advisory input (JEV) must not downgrade an R3 classification. Also required after two genuine failed GLM diagnose/repair cycles on one root cause (per the 2026-10-12 directive, genuinely hard debugging may escalate to Sol EARLY — do not mechanically burn two GLM cycles when stronger independent reasoning clearly helps) |
| `hard_engineering` (high-complexity bounded implementation) | Codex GPT-6.1 Sol MAX — proactive (owner directive 2026-10-12) | Only when ALL hold: verified admission (CLI install/syntax/model/entitlement/MAX-effort support), canonical claim + ownership permit mutation, exact mutable scope assigned, no competing worker owns the files/worktree, and a separate qualified independent reviewer is available for the exact SHA. Prefer one well-defined subproblem over whole-project transfer. GLM-5.3 MAX remains the default for routine/medium work |
| `architecture_consult` (read-only design) | Codex GPT-6.1 Sol MAX — proactive (owner directive 2026-10-12) | Read-only architecture, security/concurrency/data-integrity design, Digital Twin / advanced 3D / simulation engineering, performance investigation, complex integration and migration planning. Needs no mutation ownership |
| `read_only_advisory` | JEV | Strictly read-only; currently report `UNAVAILABLE` without a supported live route. Advisory only — never decides claim ownership, SAFE_TO_MUTATE, review acceptance, merge, completion, or risk-tier downgrade |

Owner routing policy (effective 2026-10-07):

- GPT-6 Astra is not an approved ENV route for any purpose (implementation, planning, review, escalation). Never dispatch it; never reintroduce it from stale prompts, memories, or handoffs. Historical Astra evidence in already-merged work remains valid history.
- Cost-aware route preference (cheapest safe route first): GLM-5.3 Flash → JEV advisory → GLM-5.3 MAX → GPT-6.1 Sol.
- Provider failure: if the R3 reviewer is unavailable (quota or entitlement), ordinary R2 work still proceeds with the fresh GLM-5.3 MAX reviewer; deterministic R3 review waits and is surfaced as a human gate, not as a timer. A provider-stated reset timestamp is a fallback boundary, not immutable truth; material external evidence of change permits exactly one fresh probe.
- R3 fallback designation (owner amendment, 2026-10-07 later same day, supersedes the wait-at-human-gate outcome of the previous bullet when its conditions are met): when GPT-6.1 Sol is entitlement-blocked, perform a fresh routing assessment using the deterministic R3 requirements, current canonical reviewer admission, and JEV advisory input. If another currently admitted non-GLM cross-model reviewer — e.g. GPT-5.6 Sol — satisfies the required R3 independence (different provider lineage from the authoring lane, never the author) and capability floor, designate it as the fallback R3 reviewer and proceed. This designation is per-review and must be recorded with the admission evidence. JEV remains advisory only and may not downgrade R3 or approve the review. Never fall back to GPT-6 Astra. Never silently downgrade an R3 review to same-model GLM merely to unblock progress. If no qualified cross-model reviewer is admitted, preserve HUMAN_ACTION_REQUIRED and report the exact missing capability.
- Codex-proactive roles (owner directive 2026-10-12; extends the ENV Goal, not a new claim authority): GPT-6.1 Sol at MAX reasoning effort may be used proactively — without waiting for two failed GLM cycles — as (A) read-only Advanced Engineering Architect and (B) bounded Hard-Task Implementation Specialist under the `hard_engineering` boundary above, in addition to its unchanged (C) independent R3/critical reviewer role. Independence is absolute: an implementing agent never approves its own implementation; when Codex implemented, a separate qualified cross-model reviewer reviews the exact SHA, and if none is admitted/qualified the lane stops at the typed review gate (never downgrade). Before any dispatch, verify the Codex CLI installation, supported syntax, model identity/entitlement, and MAX-effort support; an owner statement about available quota never overrides a provider entitlement error; probe at most once per materially changed admission fingerprint. GLM-5.3 MAX remains the main engineering engine; quota is a resource to use intelligently, not a reason to dispatch expensive models on trivial work. Canonical WIP limits unchanged (≤3 mutable lanes + 1 review lane; one mutable hotspot one owner; GLM and Codex parallel only on independently authorized non-overlapping tasks). Runtime `route` alignment for the two new categories is a deferred follow-up; this policy text is the durable authority.

- Routing metadata is not an authenticated identity, claim, quota, or dispatch permission.
- Treat missing, stale, reused, or contradictory provider evidence as `UNKNOWN` and fail closed. HTTP 401/403 is an authentication or entitlement result, not proof of quota exhaustion.
- Do not use Kilo's general account balance, CLI presence, a prior session export, or an online-worker indicator as proof that the `cointh-glm` proxy quota and selected upstream model are both ready.
- Never route patient-identifying data, `.env` values, or raw hospital exports to an external provider. Do not claim JEV proof by substituting another model.
- This adapter currently has no verified secret-safe live admission probe or provider dispatch implementation. Its result remains `AUTONOMY_NOT_READY`; a route selection cannot launch work.
