### 2.1 Meter-chain deltas (wastewater; P1.2 view SQL semantics vs the AppSheet formulas)

- AppSheet `คำนวณสูบ 1` (ref 802–808): `=([เลขมิเตอร์เครื่องสูบ 1]-[last_meter_สูบ1])*34`; `คำนวณสูบ 2` (ref 810–816): `=([เลขมิเตอร์เครื่องสูบ 2]-[last_meter_สูบ2])*12`; `last_meter_สูบ1/2` (ref 789–800): `=MAX(SELECT(ข้อมูลคุณภาพน้ำ[เลขมิเตอร์เครื่องสูบ n], [วันที่ บันทึก] < [_THISROW].[วันที่ บันทึก]))`; `เลขมิเตอร์เมื่อวาน` (ref 778–787): `=MAX(SELECT(ข้อมูลคุณภาพน้ำ[เลขมิเตอร์วันนี้], TRUE))` (global MAX over ALL rows).
- ENV: `wastewater.v_reading_meter_chain` (`20261115140000_parity_p1_002.sql:302-420`) — per-meter **LAG** chain over `reading_date`, spec-at-date flows (`pump1_m3`/`pump2_m3` from `core.equipment_spec`), `delta_kwh`, `meter_boundary_flag`, `streak_reset`.
- **KNOWN INTENTIONAL DIVERGENCES (each fixture carries the note + refs):**
  1. **LAG-vs-global-MAX correction** — AppSheet `เลขมิเตอร์เมื่อวาน`/`last_meter_*` take a global MAX (breaks with interleaved/out-of-order rows); ENV uses an ordered per-meter LAG. Fixtures with interleaved dates encode the ENV (corrected) expectation, citing this note + ref 778–800.
  2. **delta≤0 → NULL vs AppSheet raw difference** — AppSheet computes the raw difference (a meter reset yields a NEGATIVE `คำนวณสูบ`); ENV yields NULL + `meter_boundary_flag` on delta≤0. Reset-boundary fixtures encode NULL (never a negative, never 0), citing the P1.2 migration + this note.
  3. **spec-config vs hardcoded ×34/×12** — AppSheet hardcodes ×34/×12 (ref 807/814); ENV multiplies by the spec-at-date flow (`pump1/pump2` `flow_m3_per_h` from `core.equipment_spec`; seeded 34/12). Fixtures pin the spec-derived value AND record the AppSheet-verbatim constant in the case's citation; a spec change at a later `valid_from` yields a different factor — that is the correction, not a bug.
